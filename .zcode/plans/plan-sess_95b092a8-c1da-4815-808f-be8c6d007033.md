Festival page ("Parva") overhaul: rich Navaratri guide + shareable branded card
==============================================================================

Today's Navaratri box on Home opens `ParvaPage` (`mobile/src/screens/ParvaPage.tsx`), which renders everything as bare text (raw ISO timestamps, hyphen bullets, no imagery) — and Navaratri's published content itself is skeletal (no mantras, vidhi, or do's/don'ts; each of the 9 days says only "Remember X on this day."). The share button screenshots that plain hero block. We fix all three layers: content, presentation, and sharing.

Decisions taken: share card in **both square (1:1) and story (9:16)** with a toggle; QR/link → **https://play.google.com/store/apps/details?id=com.sanskritam.app**; content scope = **deep-fill Navaratri now (en+hi)**; the UI upgrade automatically benefits every festival.

────────────────────────────────────────
A. Backend — content depth (Navaratri flagship)
────────────────────────────────────────
1. Extend the content schema (`backend/app/services/parva_content.py`):
   - Allow a `texts[]` array inside each `series_days` entry (same shape as body-level texts: `kind` mantra|stotra|aarti|dhyana, `title`, `devanagari`, `iast`, `meaning`, source fields). This is how per-day Devi dhyana mantras reach the app.
2. Rewrite `backend/app/seeds/parva/sharad_navaratri.en.json` + `.hi.json` (mirror into `chaitra_navaratri.*.json` with an adjusted summary):
   - `summary`: 2–3 line intro. `why`: keep the 4 Devi Kavacha points, add vijayadashami significance.
   - `do.gather`: kalash, soil + barley seeds, red cloth/flowers, akshat, diya, Durga murti/photo…
   - `do.steps`: ghatasthapana + daily puja vidhi as ~8–10 numbered steps.
   - `vrat`: eat / avoid / break (kanya pujan on ashtami–navami) / who_should_eat.
   - `dont`: standard Navaratri avoidances. Unverifiable claims get `basis: "custom"`, never fabricated citations.
   - `texts`: Durga mantra ("sarva-maṅgala-māṅgalye…"), Durga Gayatri, and Durga Aarti with devanagari + IAST + meaning, citing Devi Mahatmya / wikisource where solid.
   - `series_days`: per form — who she is (summary), 3–5 worship steps (offering, colour of the day), and her dhyana mantra as a per-day `texts[]` entry.
   - **You review the Sanskrit/Hindi before this ships** — it's a Sanskrit app; the seed files will be easy to proof-read.
3. Per-day deity art in the page API (`backend/app/routers/parva.py`): each `day[]` entry gains `art_url` resolved from the existing approved-art map via key `navadurga_{form_key}`; series-level `art_url` (`sharad_navaratri`) already works. Extend the response models.
4. Art is an owner task (no paintings imported yet): the 9 Navadurga + series prompts are ready in `specs/parva-art/README.md`; you generate → `backend/scripts/parva_art_import.py` → approve. Code ships with graceful fallbacks so nothing breaks before art exists.

────────────────────────────────────────
B. Mobile — ParvaPage redesign (keep all existing logic: day selection, reminders, Ask, step player, caching)
────────────────────────────────────────
1. **Hero**: full-width festival painting (`art_url`) under a gradient scrim, Baloo 2 title, chips for date · Day N · tithi, summary below. No art → deep-fill block with large Devanagari glyph watermark (TithiCard pattern). No broken images ever.
2. **Day selector** (series): horizontal cards with per-day art avatar (`day.art_url`, fallback initial disc), date + Devi label; selected = deep fill.
3. **Deity of the day** (series): painting + Devi name + per-day summary + dhyana mantra (Tiro Devanagari Sanskrit + IAST + meaning).
4. **Muhurats**: human labels via i18n map (`sandhi_puja` → "Sandhi Puja", `parana` → "Parana", `rahu` → "Rahu Kaal", `abhijit` → "Abhijit Muhurat"); times formatted in the place's timezone ("6:52 am – 8:20 am") instead of sliced ISO strings; surface cards + "For {place}" note.
5. **Why / Vidhi / Vrat / Do & Don't / Regions**: gather as chips; numbered step cards + existing step-through modal; vrat sub-cards with ok/warn icon dots; don't-list with red icon rows; all on white `surface` cards per the October-2026 look rule (no pale fills).
6. **Mantras & Aartis**: one card per text with a kind badge, big Tiro Devanagari (`sanskritText`), italic IAST, meaning; long verses collapse with an expand toggle.
7. **Share block at the end**: on-screen preview of the card + format toggle (Square / Story) + primary Share button.
   - Card: festival painting (or styled fallback), title + date/greeting, "Sanskritam" wordmark bottom-left, **QR bottom-right in a white rounded tile** → Play Store URL.
   - Both formats rendered as fixed-dimension views (`collapsable={false}`, 360×360 / 360×640 ≈ 1080 px at x3) captured with the existing `captureRef` → `expo-sharing` flow; text-share fallback appends the Play Store link.
   - Add `react-native-qrcode-svg` (pure JS over the installed `react-native-svg`, Expo-safe) and `APP_STORE_URL` in `mobile/src/config.ts`.
8. **Loading/error**: `Skeleton` shimmer + `FetchError` retry instead of bare "Loading." text.
9. Update `mobile/src/parva/api.ts` day type (`art_url`) and i18n keys in `strings.en.ts` / `strings.hi.ts`.
